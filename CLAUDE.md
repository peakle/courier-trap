# courier-trap — контекст проекта

## Задача
Камера на фасаде у входа в ресторан распознаёт 5-значный номер курьера на термокоробе
(сервис tezkor, Ташкент) и шлёт на бэкенд события визитов. Номер — белая наклейка с тёмными
курсивными цифрами, расположена сзади короба и на боковых стенках (на боках — вертикально).
Короб жёсткий, стоит на мопеде. Курьеры стоят у входа 1–10 минут, поэтому скорость и смаз
не проблема; основные сложности — ракурс, перекрытия, ночная засветка.

## Стек и решения
- Go + GoCV (OpenCV через cgo) + Tesseract через gosseract.
- Детектор по умолчанию — эвристика `ChainDetector`: цепочка из 4–6 тёмных блобов одинаковой
  высоты в строку (adaptive threshold → контуры → группировка). Без обучения.
- `YOLODetector` (ONNX, выход [1,4+nc,N]) уже написан, бокс уточняется эвристикой.
  Компилируется, но на реальной модели НЕ проверялся (модели пока нет).
- OCR: выравнивание наклона, масштаб к высоте цифры 48 px, CLAHE (без бинаризации —
  Оцу ломает тонкие штрихи на ночных кадрах), Tesseract PSM 7, whitelist цифр,
  валидация `^\d{5}$` и порог уверенности. Уверенность считается как среднее по символам:
  у строки (RIL_TEXTLINE) она на таких кропах сплошь нулевая. Горизонтальное поле вокруг
  строки — 0.8 высоты цифры: цепочка блобов регулярно теряет крайнюю цифру.
- Поиск по цвету короба (`color.go`, флаг `-purple`, включён по умолчанию): маска H 115–175,
  S≥45, V≥100 → открытие 3x3 → контуры → bbox крупнее строки цифр, расширенные на
  max(h/4, 2·min-digit-h) и склеенные при пересечении. `ChainDetector.DetectZones` ищет
  цепочки только в этих зонах. Диапазон H широкий: ночью оттенок короба гуляет от
  сине-фиолетового (uzum bank, H~115) до пурпурного (tezkor, H~170); V≥100 отрезает
  тёмный фон (окна автобуса, небо), который иначе сливается с коробом в одно пятно.
  Предел высоты цифры внутри зоны считается от всего кадра, а не от зоны, иначе
  цифра на коробе отбрасывается как «слишком крупная».
  `-purple=false` — старое поведение (поиск по всему кадру), нужно для ч/б и ИК-камер.
- `-scale` увеличивает кадр перед детекцией (мелкие номера); координаты чтений
  возвращаются в масштаб исходного кадра.
- Визиты (`visits.go`): голосование по позициям цифр; чтение с расстоянием Хэмминга 1
  приклеивается к открытому визиту; подтверждение после `-min-reads` и согласия `-min-agree`;
  закрытие, если номер не виден `-close-after`.
- События: `visit_confirmed` (с JPEG-кропом в base64) и `visit_closed`; уникальный `event_id`
  для дедупликации. Отправка асинхронная, ретраи с бэкоффом до 1 мин на 5xx/429/сеть, 4xx не повторяются.
- Распознавание запускается при движении или раз в `-idle`, чтобы видеть стоящих курьеров.
- `-v` логирует и отклонённых кандидатов: текст, не подошедший под `-pattern`, и уверенность
  ниже `-min-conf` (`ocr.go`, `Reader.Verbose`) — без этого непонятно, кто отказал: детектор или OCR.
- `-show` — окно с разметкой (зелёный — прочитано, жёлтый — найдено, но OCR отклонил,
  голубой — ROI). На macOS окно требует главного потока: `runtime.LockOSThread()` в `init()`.
- `-annotate out.jpg` — сохранить размеченное фото (фото-режим `-image`).

## Файлы
- `main.go` — флаги, фото-режим, цикл чтения потока, детектор движения, ROI.
- `detect.go` — `ChainDetector`, `YOLODetector`, NMS.
- `ocr.go` — предобработка и Tesseract.
- `visits.go` — трекер визитов, события, снимок для окна.
- `sender.go` — очередь и отправка на бэкенд.
- `preview.go` — окно и отрисовка разметки.
- `dataset/` — реальные ночные кадры с камеры телефона (576x1280), основной регрессионный
  набор, прогонять после правок OCR/детектора. Имя файла — верный номер (разметка), 13 кадров.
  Каталог в `.gitignore`, в репозитории его нет. `-image dataset` распознаёт всю папку.

## Сборка на macOS (Apple Silicon)
- gocv НЕ поддерживает OpenCV 5 (последний gocv v0.43.0 рассчитан на OpenCV 4.13).
  OpenCV 5.0 удалена, вместо неё `brew install opencv@4` (4.14.0, keg-only) + `brew link --force opencv@4`.
  Формула `opencv@4` в Homebrew деприкейтнута, отключение 2027-07-09.
- В go.mod: gocv v0.43.0, без `replace` (replace на v0.31.0 был только для Linux-песочницы).
  Код совместим с v0.31 и v0.43: отличия API — только добавленные возвращаемые `error`.
- gosseract на darwin ищет заголовки только в /usr/local/include, поэтому:
  `go env -w CGO_CPPFLAGS="-I$(brew --prefix leptonica)/include -I$(brew --prefix tesseract)/include"`
  `go env -w CGO_LDFLAGS="-L$(brew --prefix leptonica)/lib -L$(brew --prefix tesseract)/lib"`
- Предупреждение `building for macOS-26.0, but linking with dylib ... built for newer version 26.6.2`
  безвредно; убирается `MACOSX_DEPLOYMENT_TARGET=$(sw_vers -productVersion)`.

## Камера на macOS
- `-src` принимает индекс устройства AVFoundation, список:
  `ffmpeg -hide_banner -f avfoundation -list_devices true -i ""`
  (на машине владельца: 0 — встроенная FaceTime, 1 — Camo, 2 — захват экрана;
  нумерация плавает, Camo/Continuity появляются только при подключённом телефоне).
- Без разрешения на камеру OpenCV падает с `not authorized to capture video (status 0)`
  и `Error opening device: N`. Разрешение выдаётся приложению-терминалу:
  Системные настройки → Конфиденциальность и безопасность → Камера, затем перезапуск терминала.
  Первая попытка после выдачи всё равно падает — нужен повторный запуск.

## Сборка на Linux (Ubuntu 24.04)
`apt install golang-go libopencv-dev tesseract-ocr libtesseract-dev libleptonica-dev`
— там OpenCV 4.6, нужен gocv v0.31.0.

## Запуск
```bash
./courier-trap -image dataset -scale 2                    # регрессия на размеченной папке
./courier-trap -image 'dataset/4*.jpg,photo.jpg' -scale 2 # шаблоны и файлы через запятую
./courier-trap -image photo.jpg -annotate out.jpg
./courier-trap -src 0 -show -v -idle 1s -min-reads 3          # камера Mac, отладка
./courier-trap -src rtsp://... -camera-id rest-17 -backend https://... -token "$TOKEN" -roi x,y,w,h
```

## Что проверено
- Регрессия на `dataset` (`-scale 2`, 13 кадров): верно 5 (28033 96%, 30621 85%, 43834 99%,
  45625 99%, 47616 73%), ошибочно 1 (33602 прочитан как 33002 с уверенностью 94%),
  не найдено 7 (32666, 35599, 44503, 45310, 46668, 49306, 49845 — мелкие и смазанные цифры).
  При `-scale 1` 43834 не даёт кандидата — цепочка блобов не собирается.
- Эталонное фото: 47616, уверенность OCR 96%.
- Поиск по зонам короба (`-scale 2`): те же 6 чтений, что и по всему
  кадру (47616, 43834, 45625, 33002, 30621, 28033), ложные кандидаты (вывеска «Oqtepa
  Lavash», надписи на машинах) исчезли, время кадра упало в 2–6 раз (43834: 47→20 мс,
  28033: 52→15 мс, 33602: 134→74 мс). Зоны покрывают 2–36% кадра. Самый тёмный короб
  в наборе — V=147 (45625), поэтому порог V≥100 с запасом; при V≥130 теряется 30621.
- Устойчиво к повороту ±8°, затемнению до 45%, шуму, размытию, JPEG q30, уменьшению до 0.5.
  Не читается при высоте цифры ~12 px (рабочий минимум ~15 px).
- 1080p-кадр: ~100 мс на одном ядре CPU (детекция + OCR).
- Синтетическое видео 30 с (курьер 20 с, перекрытие 3 с, вывеска с цифрами): один визит,
  14 чтений, согласие ~0.98; ошибочное чтение 47618 корректно приклеилось; вывеска отклонена OCR.
- Окно `-show` проверено под Xvfb на Linux и на macOS на видеофайле (10 с: разметка и
  статус-панель рисуются, выход по q/Esc, краша главного потока нет). На живой камере Mac
  не проверялось — не было разрешения на камеру.
- Подписи в окне рисуются шрифтом Hershey (OpenCV), кириллицу он не умеет — только латиница.

## Известные ограничения / следующие шаги
- Вертикальные наклейки на боках короба не читаются → проход детектора по кадру,
  повёрнутому на ±90°, либо YOLO с поворотом кропа.
- Цифры на вывесках дают ложные кандидаты → ограничивать зону через `-roi`.
- `MaxDigitFrac` (0.08) считается от высоты рабочей области, а не кадра: при узком `-roi`
  крупные цифры отбрасываются как «слишком высокие». Не исправлено, всплывёт на боевой камере с ROI.
- `dataset/45310.jpg` не читается: высота цифры в оригинале ~9 px (у читаемых кадров 11–15).
  Кандидат детектор находит, Tesseract на кропе возвращает пустую строку — это предел
  разрешения, а не настройка. Проверено и отвергнуто (стало хуже, не повторять):
  1) кроп из исходного кадра с одной интерполяцией вместо двух (`-scale` + масштаб к targetH):
     на одном кропе 45310 это помогало, на наборе 6 чтений → 4 (теряются 33602 и 30621);
  2) targetH больше 48 (56/64/72/96) и отказ от CLAHE: максимум 5 чтений и появляются
     уверенные ошибки — 45310 читается как «45910» с уверенностью 95%, 30621 как «30622».
  Матрица «источник кропа × CLAHE × targetH» (12 комбинаций) лучшей оставила текущую.
- Уверенность не защищает от ошибки: 33602 стабильно читается как 33002 вместо 33602
  с уверенностью 94% (`dataset/33602.jpg`). Защита — только голосование по кадрам в `visits.go`.
- Уверенность Tesseract нестабильна: одно и то же чтение при разном масштабе даёт от 0 до 99%.
  Порог `-min-conf` поэтому грубый, основная защита от мусора — голосование по кадрам в `visits.go`.
- Два курьера с номерами, отличающимися одной цифрой, одновременно в кадре склеятся в один визит.
- Очередь отправки в памяти → для продакшена спул на диск.
- Для YOLO нужен датасет: 300–800 размеченных кадров с реальной камеры + синтетика.
- Юридически: согласование камеры с владельцем фасада, табличка о видеонаблюдении.
